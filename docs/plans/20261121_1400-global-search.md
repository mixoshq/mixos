# Global search

## Context

MixOS has no way to find something without first knowing which app holds
it. A person looking for a note, a candidate or a grocery item has to open the
right app and use that app's own search, if it has one.

This adds one search over everything a person can reach: a search icon in the
menu bar and ⌘K (Ctrl+K elsewhere) open a modal in the middle of the screen,
the query goes to a single MixOS endpoint, and that endpoint asks each app the
person holds, in parallel, through a handler the app declares.

## Decisions (locked with the user)

- **An app declares what can be searched**, in a new `search` array in
  `app.json`. Each entry is one kind of object: its `name` (the handler at
  `search/<name>.ts`), a `label` for the group heading, an `icon` (required, a
  Lucide name the build checks; shown with the object in the modal and the
  settings), the `fields` that are searched (first is the title), and a `link`
  template.
- **The app answers with a server handler**, as an MCP tool does: a default
  export `(ctx: SearchContext, input) => SearchResult[]`. The platform calls it
  with `{ query, fields, offset, limit }`. The app owns its data access.
- **Matching is case-insensitive contains; title matches rank first**, then
  the other fields in the order declared, then whatever order the handler's
  query gives (recency, for most). The platform ships `searchFields()` and
  `containsPattern()` in `@/lib/apps/search` so every app ranks the same way.
  The query builder has no `or()`, so `searchFields()` runs one query per field,
  in priority order, and merges them without duplicates.
- **The deep link template lives on each object in `app.json`.** `link` is a
  path relative to `/apps/<slug>/`, optionally with a query string, with
  `{placeholder}`s filled from the result (`{id}`, or a key the handler returns
  in `params`). App pages have literal paths (no dynamic segments), so
  placeholders go in query values only; the build checks the path names a real
  page. Every value is URL-encoded, and the link can only ever point inside the
  app. Selecting a result closes the modal and navigates there.
- **Installed apps are searchable by name**, as an "Apps" group: typing `cal`
  offers to open Calendar. Only apps with pages, that the person installed and
  holds.
- **Results are grouped by app.** Within an app, each object shows its top 5,
  then **Show 10 more**, repeatable until there are no more.
- **Arrow keys** move the highlight through every row, Show more rows
  included; Enter opens it; Escape closes. The input is a combobox over a
  listbox, with `aria-activedescendant`.
- **`/account/search`, a Search page in My Account**: drag to reorder which
  app's results come first, a switch per app to stop searching it, a switch
  per object of each app (listed with its fields as code) to stop searching
  just that, a switch to hide the menu-bar icon and a switch to turn off the
  shortcut. An object's switch is inert while its app is off, and keeps its
  state for when the app is switched back on.
  With both off, search is not available at all: no icon, no shortcut, and the
  endpoint refuses.
- **Preferences are per person, in the database** (migration 0003,
  `user_search_preferences`), so they follow the person between browsers. Apps
  not yet in a person's order go to the end, and are searched: a new app is on
  until it is switched off.

## Structure

### The manifest

- `src/lib/apps/types.ts`: `SearchObjectDefinition`, `AppManifest.search`.
- `scripts/manifest-schemas.ts`: `searchObjectSchema`, at most 5 objects per
  app, at most 6 fields each, `link` shape checked.
- `scripts/generate-project-registry.ts`: `validateSearchObjects()` — handler
  on disk with a default export, unique names, the link's path resolves to a
  page of the app, placeholders are identifiers. `search/<name>.ts` is an entry
  point held to the containment scan (`unscannedEntryPoints`).
- `docs/schemas/app/v1.json` regenerated (`npm run schemas`).

### The handler contract

- `src/lib/hooks/types.ts`: `SearchContext` — the MCP tool context's
  read-only shape (read-only `db`, connectors narrowed to reads, no
  notifications or hooks), with `caller: { kind: "search" }`.
- `src/lib/apps/search.ts` (on the import allowlist): the input and result
  types, `containsPattern()`, `searchFields()`, `matchesQuery()` for data held
  in memory.
- `src/lib/apps/read-only-context.ts`: the narrowing that `buildMcpToolContext`
  did inline, shared by the MCP broker and the search broker so the two can
  never drift.

### The broker and the endpoint

- `src/lib/search/broker.ts`: `runSearchObject()` — the app gate, then import
  `@apps/<slug>/search/<name>`, build the read-only context, run with a 5s
  timeout, validate the output (`id`, `title` ≤ 200, `subtitle` ≤ 300, string
  `params`), fill in the link, and report `hasMore` by asking for one more row
  than it shows. A handler that throws or times out costs only its own object.
- `src/lib/search/server.ts`: `globalSearch()` — which sources the person can
  search (held apps declaring `search`, in their order, not switched off), the
  Apps group, the fan-out.
- `src/app/api/search/route.ts`: `GET /api/search?q=` for every source's first
  page, `&app=<slug>&object=<name>&offset=<n>` for Show 10 more. Session only,
  rate-limited per person, refuses when the person has search off.

### Preferences

- `supabase/migrations/0003_user_search_preferences.sql`.
- `src/lib/search/preferences.ts` (read/write), `src/lib/search/actions.ts`
  (server actions for the settings page).
- `src/components/search/search-context.tsx`: the provider in the main layout,
  seeded from the server so the icon never flashes; owns the shortcut listener
  and the modal.

### UI

- `src/components/search/search-button.tsx`: the icon, before the gift.
- `src/components/search/search-modal.tsx`: the modal.
- `src/app/(main)/account/search/page.tsx` and
  `src/components/search/search-settings.tsx`; a Search entry in
  `ACCOUNT_SECTIONS`.

### Docs and the template

- `docs/apps/search.md`, linked from `apps/AGENTS.md` as a guide and an
  invariant, and from `docs/apps/architecture.md`'s field reference.
- `apps/_template`: a `search/greetings.ts` example over an in-memory list,
  with a `greetings` page it links to.

## Verification

- Unit tests: link filling and encoding, `searchFields()` ordering, dedupe and
  paging, `containsPattern()` escaping, preference ordering.
- `npx tsx scripts/generate-project-registry.ts`, `npm run typecheck`,
  `npm run lint`, `npm test`.
- In the browser: ⌘K opens the modal, arrows move, Enter navigates, Show 10
  more pages; the settings page reorders, switches an app off, hides the icon,
  turns off the shortcut, and with both off the icon and shortcut are gone.
