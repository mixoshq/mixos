# App escapes: one declared exception, enforced by the build

## Context

`escapes` was meant to be the valve in the hardening plan's enforcement ladder
— "explicit, declared and visible" (decision 8 of
[`20260824_2012-app-platform-hardening.md`](20260824_2012-app-platform-hardening.md)).
What shipped is a label, not a valve. Declaring an escape enables nothing, and
not declaring one blocks nothing:

- **`raw-response` and `output-validate-dev-only` are unchecked.** A route with
  `raw: true`, or with `output: { schema, validate: "dev-only" }`, works the same
  whether or not the manifest declares the escape (`src/lib/apps/route.ts`).
- **`process-env` and `raw-fetch` are ESLint-only.** A disable comment silences
  either, and nothing compares it with the manifest. Lint runs on pull requests
  to this repository and nowhere else, so for an extension installed from the
  Registry both bans are advisory. `globalThis.fetch(…)` passes the `fetch` ban
  even here, because `no-restricted-globals` only matches the bare identifier.
- **`raw-html` has no rule behind it at all.** Nothing flags
  `dangerouslySetInnerHTML`.
- **Declared escapes are shown nowhere.** `docs/apps/architecture.md` says they
  appear on the app's admin page; nothing under `src/` renders them, and the
  mixos.org listing does not either.
- **No app uses any of them.** No first-party app declares an escape or uses
  any of the five escapable constructs, so narrowing the set breaks nothing.

Apps run in the same server process as the platform, with no sandbox. Two of
the five escapes reach exactly what that arrangement depends on keeping out of
an app's hands: `process.env` holds `SUPABASE_SERVICE_ROLE_KEY` (every table,
past RLS) and `CONNECTOR_ENCRYPTION_KEY` (every stored credential), and a raw
`fetch` is the SSRF and exfiltration path that `context.http` exists to close.
A reviewer told "this app declares `process-env`" is being asked to approve an
app that can read the keys to the whole instance.

## Decisions

| # | Decision |
|---|---|
| 1 | **`process-env` is no longer escapable.** The `env` manifest field already covers every legitimate need: admin-filled, app-scoped, `password` values encrypted at rest. |
| 2 | **`raw-fetch` is no longer escapable.** Outbound calls go through `context.http` (bounded by `egress`) or a connector. If `context.http` cannot do something an app needs, that is a platform gap to fix, not a rule to escape. The browser side is already fenced by `connect-src 'self'` (`src/proxy.ts`). |
| 3 | **`raw-html` is no longer escapable.** Apps get a `Markdown` primitive (`@/components/ui/markdown`) that renders Markdown and drops raw HTML, so sanitizing is the platform's job, not each app's. The HTML sinks are banned outright. |
| 4 | **`raw-response` stays, and becomes load-bearing.** File downloads, streams and redirects are real needs, and the risk is small: a raw route still passes the dispatcher's auth tier, role gate, CSRF check, rate limit and budget — it only owns its own Response. A route with `raw: true` now registers only if `app.json` declares `raw-response`. |
| 5 | **`output-validate-dev-only` is removed, with the `validate: "dev-only"` option.** Nothing uses it, and it only ever turned a production validation failure into a log line — the parse still ran, because the parse is also what strips undeclared keys. It can come back if someone measures a need. |
| 6 | **Enforcement moves to the registry generator.** The generator runs on every build and on every Registry install (step 9 of `src/lib/repository/install.ts`), so a check there covers third-party code. Lint stays, as the fast feedback in an editor. |
| 7 | **A violation skips the app; it does not abort the run.** The install path maps a `Skipping <slug>/` line to `rejected-by-registry` and rolls the directory back, which is the right verdict on the extension. A non-zero exit is reported as "this instance could not run its generator — nothing is wrong with the extension", which would be false here. |
| 8 | **Declared escapes are shown on the app details dialog**, as the docs have claimed since the hardening plan. |

## What the build rejects

Read from the TypeScript syntax tree of every source file under
`apps/<slug>/` (`.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`), so comments and
strings never trigger it. Each finding names the file and line.

| Construct | Why |
|---|---|
| Any reference to `process`, including `globalThis.process`; importing `process` or `node:process` | The raw environment and the platform's secrets |
| Any reference to `fetch`, or `.fetch` on `globalThis`, `window`, `self` or `global` | Unbounded outbound requests: SSRF and exfiltration |
| `WebSocket`, `EventSource`, `XMLHttpRequest` | The same, by another constructor (Node 22 has a global `WebSocket`) |
| Importing `http`, `https`, `http2`, `net`, `tls`, `dgram` (with or without `node:`), or an HTTP client package (`undici`, `node-fetch`, `axios`, `got`, `ky`, `superagent`, `cross-fetch`, `isomorphic-fetch`) | The same, by import |
| `dangerouslySetInnerHTML`; assigning `.innerHTML` or `.outerHTML`; `.insertAdjacentHTML(…)`; `document.write(…)` / `writeln(…)` | Markup the app did not author: XSS. Use the `Markdown` primitive |
| `eval(…)`, `new Function(…)` / `Function(…)` | Running a string as code, which is how every check above would otherwise be routed around |
| A name built at runtime: `globalThis[name]` (or on `window`, `self`, `global`), and `require(…)` / `import(…)` of anything but a string literal or a relative template path | The same, by indirection |
| A route with `raw: true` when `app.json` does not declare `raw-response` | The one remaining escape, now required |

### What this is not

A sandbox. The scan reads syntax, and code determined to evade it can still
assemble a property name at runtime or reach the same object through another
module. What it does is make accidental and naive use impossible to ship, and
make evasion conspicuous in review. The complete answer to "what may an app
import" is the closed import graph in the app-packages plan (on
`feat/linux-wsl-docker`, proposed), which this neither replaces nor depends on.

## Verification

1. `npm run registry` — the first-party apps register unchanged.
2. Throwaway fixture apps, one per row of the table above, are each skipped
   with a message naming the file and line — and a fixture with `raw: true`
   *and* a declared `raw-response` registers. Fixtures are removed afterwards;
   the generator's output format is what `install.ts` matches, so a skip here is
   a `rejected-by-registry` install by construction.
3. A manifest declaring `process-env` fails schema validation with the closed-set
   message.
4. `npm run typecheck`, `npm run lint`, `npm run build`.

## Adjacent gaps found, not closed here

1. **The raw-palette and `dark:` lint rules do not run on app components.** Two
   config blocks set `no-restricted-syntax` for `apps/**/*.tsx`, and the later
   one (raw elements) replaces the earlier one's options rather than merging
   with them — `npx eslint --print-config` on an app widget shows only the six
   raw-element selectors. The palette rules hold for `apps/**/*.ts` and for
   `src/`, but not for the `.tsx` files where colour classes actually live.
   Fixing it means merging the two selector lists, and may surface existing
   violations whose fix is a visual decision per app, so it belongs in its own
   change.
2. **The docs site follows.** mixos.org's publishing guide lists `escapes` among
   what reviewers check, and its generated reference pages copy
   `docs/apps/architecture.md`; both update once this merges and the docs are
   synced.
